## 三、环境搭建步骤

### 3.1 安装 Ollama

Ollama 是本地跑大模型的工具，一条命令下载、一条命令运行，不需要配深度学习环境。

```bash
# 用 winget 安装（Windows 包管理器）
winget install --id Ollama.Ollama -e

# 手动启动服务（默认监听 11434 端口）
"C:\Users\Lenovo\AppData\Local\Programs\Ollama\ollama.exe" serve
```

验证服务是否启动：
```bash
curl http://localhost:11434/api/version
# 返回 {"version":"0.33.3"} 即成功
```

### 3.2 拉取模型

```bash
ollama pull qwen2.5:0.5b          # 生成模型（问答用，397MB）
ollama pull nomic-embed-text      # 嵌入模型（向量化用，274MB）
ollama pull llama3.2              # 生成模型（3B，更大更聪明，2GB）
```

查看已装模型：`ollama list`

### 3.3 创建 Python 环境（关键）

因为要用 llama-index（依赖 torch、transformers 等重量级库），必须用**独立虚拟环境**，别污染系统 Python。

```bash
# 用 Python 3.13 建虚拟环境
D:\python.exe -m venv venv

# 激活（PowerShell）
.\venv\Scripts\Activate.ps1

# 安装依赖
pip install ollama openai                       # 实践1
pip install llama-index-core llama-index-llms-ollama llama-index-embeddings-ollama   # 实践2/3
pip install sentence-transformers llama-index-embeddings-huggingface                 # 实践3改进
pip install flask                               # 网页问答界面
```

> **为什么用 3.13 不用 3.14**：llama-index / torch 等库对最新版 Python 适配往往滞后，
> 用稍旧的稳定版（3.13/3.12）安装最不容易报错。

## 四、最关键的坑（新手一定要看）

这一节是实操中实测踩到并解决的坑，**你大概率也会遇到**，直接照着处理。

### 坑1：Ollama 认不出显卡（探不到 GPU）

**现象**：`ollama serve` 日志里只有 `inference compute id=cpu`，`total_vram="0 B"`，
明明有 RTX 3050 却完全没用到，模型只能 CPU 跑（巨慢）。

**原因**：Ollama 默认的 CUDA 后端在这台笔记本上探测 GPU 失败（子进程崩溃）。

**解决**：改用 **Vulkan 后端**（RTX 3050 支持 Vulkan 加速）：
```bash
set OLLAMA_LLM_LIBRARY=vulkan && ollama serve
```
启动后日志能看到 `library=Vulkan ... NVIDIA GeForce RTX 3050 Laptop GPU` 就成功了。

### 坑2：3B 模型在 4GB 显存上「生成卡死」

**现象**：用 `llama3.2`（3B）时，模型能加载到 GPU（日志显示 `offloaded 29/29 layers to GPU`），
但**生成回答时卡死**——一直转圈不输出。

**原因**：4GB 显存装不下 3B 模型权重 + 上下文缓存 + 计算缓冲，内存分配失败但不报错。

**解决**：**换小模型** `qwen2.5:0.5b`（397MB）。小模型在 3050 上流畅生成。
完整结论：**4GB 显存只能用 0.5b~1b 级别的小模型**，3B 起步就得 CPU 慢跑。

### 坑3：llama-index 报「内存不足 / KV cache 爆了」

**现象**：`Ollama(model="llama3.2")` 时报
`failed to allocate buffer of size 14495514624`（约 **14.5GB**）。

**原因**：llama-index 的 Ollama 类默认上下文窗口很大（约39000），触发超大 KV cache。

**解决**：限制上下文大小 `Ollama(model=..., context_window=4096)`，或用小模型。

### 坑4：残留进程吃掉 3.5GB 内存

**现象**：明明内存有 16GB，可用却只剩 0.6GB，加载模型报
`failed to allocate CPU_REPACK buffer`。

**原因**：之前跑 Ollama 派生的 `llama-server.exe` 子进程没退出，**占着 3.5GB**。

**解决**：杀掉残留进程，内存立刻恢复：
```powershell
Get-Process llama-server | Stop-Process -Force
```

### 坑5：中文乱码

**现象**：Python 输出中文变乱码。

**解决**：运行前设置 `set PYTHONIOENCODING=utf-8`，或 `chcp 65001`。

### 坑6：curl 测试中文接口报 400

**现象**：用 curl 往 Flask 接口发中文 JSON 报 400 Bad Request。

**原因**：Windows 的 curl 对中文 Body 编码处理有问题。

**解决**：这是**测试工具**的问题，真实浏览器（网页前端）不会遇到。用 Python 或浏览器测即可。

## 五、各实践代码与真实运行结果

### 实践1：访问本地 LLM

**（1）Ollama 方式** `p1_ollama_way.py`
```python
import ollama
response = ollama.chat(
    model="qwen2.5:0.5b",
    messages=[{"role": "user", "content": "请用一句中文介绍你自己，并说明你是什么模型。"}],
)
print(response["message"]["content"])
```
真实输出：
> 我是阿里云团队的Qwen模型，也是阿里云的超大规模语言模型之一。我由阿里云团队开发和维护，
> 旨在帮助用户解决各种问题和需求。我能够理解中文，并且具有语言模型的性能，能够回答问题、
> 创作文本以及处理自然语言任务。

**（2）OpenAI 方式** `p1_openai_way.py`
```python
from openai import OpenAI
client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
resp = client.chat.completions.create(
    model="qwen2.5:0.5b",
    messages=[{"role": "user", "content": "请用一句中文介绍你自己。"}],
)
print(resp.choices[0].message.content)
```
真实输出：
> 我是来自阿里巴巴集团的人工智能训练与开发平台，专门处理和优化诸如「你好，世界」…类型的自然语言对话。

（两种方式区别：Ollama 方式用官方原生 API；OpenAI 方式用 OpenAI 兼容接口，方便以后接其它应用。）

### 实践2：使用 llama-index 嵌入文件

`p2_llama_index_embed.py`
```python
from llama_index.core import Settings, VectorStoreIndex, SimpleDirectoryReader
from llama_index.llms.ollama import Ollama
from llama_index.embeddings.ollama import OllamaEmbedding

# 设置本地模型
Settings.llm = Ollama(model="qwen2.5:0.5b", base_url="http://localhost:11434")
Settings.embed_model = OllamaEmbedding(model_name="nomic-embed-text", base_url="http://localhost:11434")

# 加载本地文件 → 建立索引 → 查询
documents = SimpleDirectoryReader("data").load_data()
index = VectorStoreIndex.from_documents(documents)
query_engine = index.as_query_engine()
response = query_engine.query("Ollama 支持哪些模型？常用命令有哪些？")
print(str(response))
```
真实输出（从本地文件检索到的答案）：
> 已加载 1 个文档
> Ollama 支持多种开源模型，例如 Llama 系列、Qwen 通义千问系列、Mistral 等。常见的命令包括：
> `ollama pull <模型名>`：下载模型到本地
> `ollama run <模型名>`：运行模型并进入交互对话
> `ollama list`：查看本地已下载的模型
> `ollama rm <模型名>`：删除本地模型
> `ollama serve`：启动 Ollama 服务（默认 11434 端口）

### 实践3：添加向量索引（多轮问答）

`p3_vector_index.py` 在实践2基础上加了带记忆的多轮问答引擎，连续问了 3 个问题：
```
问题: Ollama 支持哪些模型？
回答: Ollama 支持多种开源模型，例如 Llama 系列、Qwen 通义千问系列、Mistral 等。

问题: Ollama 默认监听在哪个端口？
回答: Ollama 默认监听在 11434 端口。

问题: Ollama 如何实现 GPU 加速？
回答: 在有 NVIDIA 显卡的机器上，Ollama 会自动利用 CUDA 进行推理加速；在没有 GPU 时也可以退回到 CPU 运行，只是速度会慢一些。
```
三个问题全部检索到本地文件的准确内容并回答正确。

## 六、网页问答界面（实战应用）

把实践做成一个**像 ChatGPT 一样的聊天网页**，一问一答。

### 组成
- `chat_server.py`：后端（Flask），调用本地 Ollama，监听 5000 端口
- `chat_front.html`：前端聊天界面（深色终端风）
- `start_llm_chat.bat`：一键启动脚本

### 启动方式
**双击 `start_llm_chat.bat`**，它会自动：
1. 检测并启动 Ollama 服务（11434）
2. 检测并启动问答服务（5000）
3. 打开浏览器到 `http://127.0.0.1:5000`

### 两种问答模式（右上角切换）
| 模式 | 说明 | 对应实践 |
|------|------|---------|
| **直接对话** | 模型凭自身知识直接答 | 实践1 |
| **查本地资料** | 先检索本地文件再答（答案有出处） | 实践2/3 |

### 实测回答示例
- 纯对话：「我叫通义千问，我是一个超大规模语言模型，可以回答问题、创作文字和绘画等。」
- 查本地资料：「Ollama 支持多种开源模型，包括 Llama 系列、Qwen 通义千问系列、Mistral 等。」

## 七、断网能用吗？

**能。** 因为整个问答链路（模型 + 嵌入 + 服务）都跑在 `127.0.0.1` 本地回环地址，物理上不经过外网。

| 模式 | 断网能答 | 原因 |
|------|---------|------|
| 直接对话 | ✅ 能 | 模型是本地文件 |
| 查本地资料（界面里） | ✅ 能 | 用 nomic-embed-text（本地） |
| 实践3改进（m3e-small） | ⚠️ 首次需联网 | 要从 HuggingFace 下载模型 |

> 唯一的例外：`p3_improved_hf.py` 首次运行会联网下载 m3e-small，下载一次后就缓存了。

## 八、模型性能评价（qwen2.5:0.5b）

这是 0.5B = 5亿参数的**超小模型**，是 4GB 显存笔记本能流畅跑的量级里效果最好的之一。

| 维度 | 表现 | 说明 |
|------|------|------|
| 常识/逻辑 | 中等偏上 | 简单问答、结构性问题答得好 |
| 代码 | 不错 | 生成简单代码、示例可靠（实际测过 Java 示例答得很完整） |
| 数学/推理 | 弱 | 多步推理、复杂计算易出错 |
| 中文 | 好 | 通义千问中文是强项 |
| 知识广度 | 弱 | 记不住太多事实，冷门知识会编 |
| 长文本 | 弱 | 上下文有限，长对话易忘前文 |

**定位**：适合**断网、轻量、教学、日常问答**。不能替代 DeepSeek/GPT 等大模型做严肃复杂任务。
另有更大的 `llama3.2 (3B)` 更聪明，但 4GB 显存跑不动（会卡死），只能 CPU 慢跑。
